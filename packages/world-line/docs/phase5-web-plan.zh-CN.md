# Phase 5：Web 能力补齐与可靠性实施方案

状态：Phase 5 与后续增强已实施，当前验收以 [遗留项台账](completion-ledger.zh-CN.md) 为准。更新日期：2026-09-08。本文后半保留最初核实和设计要求。

核实基线：提交 `70a30cf` 加当前工作区已暂存的世界线改动；不是仅按该提交或旧版设计文档判断。最初核实轮只增加方案；随后经用户要求在当前工作区实施。实现过程中仅使用临时夹具验证变更和回收，没有安装/卸载用户插件、合入实验或清理真实数据。

后续实施顺序及事务恢复进度见 [可靠性实施记录](./reliability-roadmap.zh-CN.md)。

- P3b：同来源队列、独立来源并行、CLI/Web 操作锁、认证 SSE 有界重放、重连快照重置、退避轮询、缓存索引、watcher 和 revision/since 行增量已接入。当前保守串行化同来源验证，不实现并行克隆的更细资源模型。SSE 重放窗口驻内存，最终状态和探针落盘；服务器重启从持久任务快照重置。提交幂等键已落盘；pending 不自动重放。

## 1. 结论与实施顺序

反馈中的主要能力缺口成立。优先补齐“查看当前组成 → 升级/卸载 → 独立验证 → 查看结果和差异 → 合回来源”闭环，然后建设任务台、历史比较与存储治理。当前已实现基于主干/普通分支验证及合回来源、实验侧栏收纳，这两项作为后续所有入口的共同基础。

建议拆成以下交付批次，每批独立 PR 和验收，避免一次重写整个管理器：

| 批次 | 交付 | 前置条件 | 规模 |
| --- | --- | --- | --- |
| P0 | API action 注册表、参数校验、资源归属检查、面板状态收敛 | 无 | 中 |
| P1 | 组成面板、升级/卸载验证、报告和日志查看 | P0 | 中至大 |
| P2 | 历史快照比较、配置变更验证、搜索快捷键 | P0；复用 P1 的验证流程 | 中 |
| P3a | 持久化任务台、重启后的状态核对、站内完成提醒 | P0/P1 | 大 |
| P3b | 按资源排队、安全并发、任务事件推送、世界线增量更新 | P3a、操作锁审查 | 大 |
| P4a | 存储统计、保留策略解释和清理预览 | P0；统计可提前 | 中 |

### 需要修正的判断

1. **SSE 不是降低扫描成本的充分条件。** 如果服务端仍每秒运行 `worldLines` 再推送，只是把轮询搬了位置。应先复用任务内部事件，世界线再用版本索引与缓存，保留外部 CLI 写入的发现机制。
2. **现有锁不足以直接放开并发。** create 有来源 profile 锁；服务启停/删除还有管理目录级 `.service.lock`；promote 的快照、交换、重启检查、回滚跨多个临界区。`runLabTransaction` 未显示一个覆盖全生命周期的同实验操作锁。两个 job 不同不意味着资源无冲突。
3. **持久化记录不等于续跑执行。** pnpm、浏览器、合入交换被中断后都可能存在部分结果。禁止重启后直接把旧 runner 从头再执行。
4. **保留策略本身可能阻止有效清理。** [vault/retention.ts](../src/vault/retention.ts) 的 `protect` 递归保留父链；最新快照已被保护，线性历史可能全部被保留。先明确父链语义，不能承诺 prune 会释放大量空间。
5. **GC 不必先引入持久化引用计数。** 可先做完整标记与清扫，但必须保证扫描期间没有未提交引用被误判为垃圾。
6. **来源字段不自动证明核心完整。** 已出现行的 bundle 标签不能证明缺失行本应存在；仍需版本对应的预期核心清单或可信基线，也不能用最终候选 dump 自己证明自己完整。

## 3. P0：为新增能力建立共同边界

### API

采用 action 注册表，每项声明：参数 schema、读写类别、目标资源解析、响应类型、执行函数。前端共享类型；运行时仍做校验。可用小型类型化校验器或仓库适配的 schema 库，不为“声明式”目标强行引入大框架。

统一解析 `sourceId`/`lineId`/`labId`/`snapshotId`，客户端不传可信绝对 home 路径。分支 ID 解析后验证 profile、purpose、生命周期和来源关系；归属校验必须适用于报告、比较、下载等读操作。schema 不能替代授权。

保留宿主认证、同源写入检查；明确字符串长度、请求体大小、枚举和不允许的组合。通过字段白名单避免调用方覆盖 ctx、home、锁路径和任务结果。

### 面板

用一个 `PanelState` 联合类型表示活动面板，例如组成、实验、验证、报告、历史、比较、维护。独立保留模态确认框状态和任务中心状态；统一 `openPanel`、返回栈与恢复焦点。

长任务执行与面板解绑。切到对比面板时验证继续，任务栏可返回结果。首期不实现自由拖动的多窗系统；若之后需要同时展示两份内容，再扩展主/副两个明确槽位。

验收：连续执行“组成 → 验证 → 比较 → 任务 → 报告”只出现预期面板；关闭面板不丢任务；未知/越权 ID 在读写入口都被拒绝。

## 4. P1：插件管理与诊断闭环

### 组成面板

主干/普通分支右键新增“查看组成”。以 `analyzeProfile` 返回可展示 DTO，不返回原始配置或秘密字段。

每行显示包名、声明规格、锁文件解析版本、安装方式、是否属于 bundle、本地路径与存在性；解析失败和版本未知必须显式标注。路径存在不代表已成功加载，依赖声明不代表插件正在运行。无法确认的运行态不显示绿色正常。

行操作：升级、卸载、查看差异。本地 file/link 依赖用“重新验证本地版本”，不暗示包仓库存在更新；核心 bundle 的操作要明确影响并经过同样的核心完整性校验。

“查看差异”必须有明确比较基准：进入选择器选某个快照或已有实验；新建升级实验后，默认比较实验与其创建时的来源快照，避免直接拿不断变化的实时来源作为唯一依据。

### 更新与卸载

新增 `composition`、`lab-update`、`lab-remove`，复用现有 runVerb 和 sourceId 追踪。JobKind、任务中文名、结果页、历史归类同步扩展，不能只在后端接函数。

升级默认要求目标版本/规格；可提供“采用最新兼容版本”显式选项，但实验结果须显示实际解析版本。卸载确认页显示精确包名和来源环境，验证完成后才允许合回来源。

共同流程：选择变更 → 实验内应用 → compose/HTTP/浏览器探针 → 显示差异和验证证据 → 明确合入目标 → receipt 冲突检查 → 合入。失败保留实验并提供报告、重验；不得通过自动接受 inconclusive 掩盖失败。

### 报告与日志

Web 返回 `ReportResult` 的脱敏 DTO，报告面板按 sections 展示探针、日志尾部和诊断说明。支持复制/下载脱敏 JSON；文件名使用 reportId。可首期用响应数据生成 Blob 下载，避免新增任意文件读取端点。

如增加持久报告读取，用 reportId 和受控目录解析，加归属验证，禁止接受用户提供的任意文件路径。日志接口必须使用固定日志种类、行数与字节上限，并在输出前脱敏；当前 readTail 会读完整日志后截尾，需要改为有界读取。

失败探针旁提供“查看相关日志”；无法精确映射时显示“本次验证日志”，不要把整次运行的尾部冒充该探针独有日志。报告损坏或部分缺失仍展示已有内容和缺失原因。

验收：主干与分支都覆盖升级成功、卸载失败、浏览器登录未完成、receipt 冲突、本地路径失效；分支失败/合入不得修改主干；报告响应、复制内容和下载内容都通过脱敏测试。

## 5. P2：历史比较、配置变更和可发现性

新增带显式引用类型的比较接口：每侧为当前环境或历史快照，并携带所属 lineId；不要只传一个全局 snapshotId。

- 快照 ↔ 快照：复用 `diffManifests`，两个快照分别校验所属 profile/home。
- 快照 ↔ 当前：当前侧记录读取时间和 receipt；展示“当前状态已变化”提醒，不伪装成不可变比较。
- 展示依赖变化、配置结构变化、可恢复性及缺失/脱敏数据；不得展示未脱敏配置全文。

`lab-config-apply` 面向高级用户：Web 提交有限大小的 YAML 文本，服务端写到受控临时位置供现有命令读取，任务完成清理；禁止浏览器任意指定宿主文件路径。不能执行 `!!js` 做前端或服务端预览求值。

增加 `/` 搜索世界线；Cmd/Ctrl+K 命令面板检索世界线与允许的操作。输入框、编辑器、组合输入期间不拦截普通键。卸载、清理和合入仍进入确认步骤，不因键盘命令直接提交。

UI 保持中文，CLI 保留稳定命令名与机器可解析状态，错误采用稳定 errorCode + 可读说明，README 分开快速使用和开发协议。状态文案明确区分“正在运行”“待浏览器验证”“待合入”“已合入”，tooltip 解释下一步，不要求用户理解 clientGate 枚举。

验收：同一分支的旧快照对当前差异正确；跨 home 同名快照不串读；无内容泄露；快捷键不劫持文本输入。

## 6. P3：任务台、并发与事件流

### P3a：先解决重启丢记录

任务记录放入 `world-line/jobs/`，带 schemaVersion、jobId、action、资源引用、脱敏参数摘要、状态、时间、probe/event 序号、结果引用和中断原因。目录/文件权限受限；不记录原始密钥、登录 URL、未经脱敏的配置正文。

记录持久化成功后才返回已接收。采用原子快照加有界事件日志；规定完成任务保留天数/数量，任务台能分页查看。状态包括 queued/running/succeeded/failed/interrupted；明确业务验证失败与执行异常。

重启时对原 running 记录核对实验 manifest、journal 和进程身份，保守标记 interrupted，显示“查看报告 / 重验 / 新建任务”。保留成功结果；不凭 PID 单独认领进程，不自动重放安装、promote 或 restore。不可恢复的队列参数应请求用户重新提交，不能用脱敏摘要当可执行参数。

任务台固定入口与未读结果标记、站内通知常驻；后台页面可更新标题中的未读数量，不持续闪烁。系统通知仅在用户主动开启后请求权限，拒绝权限不影响站内通知；通知不携带路径、日志、插件配置。

### P3b：再放开并发并改推送

定义任务资源集合和固定加锁顺序：manager、profile、来源分支、实验、vault、service registry。不同实验可并行；同一实验重验/删除互斥；来源合入/删除与依赖它的操作互斥。安全的多资源任务队列要覆盖完整操作周期，不靠只包住文件交换的短锁防止后续回滚覆盖别人的写入。

同来源只读克隆与验证可按模型并行，合回同一来源排队并重新检查 receipt。不要让任务级锁和内部 profile 锁递归死锁；为 CLI 与 Web 的并发也提供共同的操作锁协议。

任务内部 phase/probe/settled 变化先持久化，再产生递增序号事件。增加认证同源 SSE，支持 Last-Event-ID、心跳、断线补发、有限重放窗口和超窗重新取快照；服务器重启不会产生重复完成通知。断线时保留退避轮询作为兼容路径。

世界线先建立缓存索引：manifest/journal/快照索引变化驱动脏标记；运行健康状态用独立、有并发上限和超时的轮询。外部 CLI 文件变化通过 watcher 加周期性校对发现，不能只订阅 Web 自己的操作。客户端用 revision/since 获取变化行和删除标记，不每个订阅者触发完整扫描。

验收：A/B 两个独立来源任务可以并行；同目标操作有确定顺序；源分支删除、重启中断、重复提交、SSE 断线/重放、CLI 并发全部测试。以 100/1000 条实验夹具测量读取次数与延迟，证明空闲订阅不再按“客户端数量 × 全量扫描”增长。

## 7. P4：空间治理

### P4a：先报告空间，再预览清理

按管理目录、每个分支、验证实验、救援实例拆分 manifest/对象/secret bundle/log/report/job/pnpm-store/home 数据。区分逻辑大小、可获取的已分配空间与可回收估算；识别硬链接避免简单累加双算，不把 APFS 克隆等共享空间的估计声称为精确释放值。

扫描异步运行、缓存结果并显示扫描时间；限制并发，不跟随符号链接扫描管理目录之外。正在变化的目录给估计标签；权限不足给部分结果。空间统计不能放入每次 worldLines GET。

保留策略预览展示将删除的快照、保护原因和预计释放类别。先明确父链是历史导航还是恢复依赖；未证明独立可恢复前，不修改现有父链保护规则。若需要保留独立快照而断开历史链，必须制定兼容的墓碑/导航策略，不静默重写不可变 manifest。

### P4b：可审计的回收

GC 的引用根至少包括所有保留 snapshot 的 files/homePatch、稳定点与最新快照引用、仍存活实验/恢复操作所需 snapshot、未完成事务和 journal 的恢复依赖；逐字段核对后再定最终集合。不同 home/vault 单独确定对象命名空间，不假设所有引用都在根管理器。

采用 mark → 候选清单 → 应用前重新校验 → 隔离回收目录 → 延迟永久删除。所有对象发布/引用提交与 GC 使用兼容的 vault 锁或等效 generation 协议；快照写入者必须参与，不能仅给 GC 加一把其他人不用的锁。损坏或未知格式的根导致停止删除并报告。

Web 默认 dry-run，确认页固定计划版本、对象数、逻辑字节与估算空间；应用时变化则要求重新预览。禁止扫描后未经复核直接 unlink。运行中实例、安装中的 store、活动日志不参与回收。

验收：共享对象只回收无引用者；homePatch 引用不漏；损坏 manifest、写入竞争、跨 profile、软链接、重复执行、恢复隔离数据均覆盖；回收后保留快照仍可做还原验证。

## 8. Compose 安全专项

扩展 `ComposedRow` 的来源信息（bundle/sourceKind/可信度），并保留原始结构分析能力。使用能保留注释位置的解析方式或宿主结构化输出；不能简单按正则切开 YAML，因为 block scalar、嵌套 insert、跨段别名可能让切段错误。

建立真实宿主版本的 dump fixtures：多个 bundle、嵌套行、无标记、重复 ID、patch 插入、字符串里伪造 `# ==`、锚点/别名。核心预期集合来自可信模板/版本基线；缺来源不视为通过，缺核心行给明确失败项。

保留现有 pristine-template 对比作为补充，直到静态断言有同等证据。新字段先可选兼容旧数据；老记录无来源时显示未知，重验获取新证据。

## 9. 交付约束与开放问题

- 每批同步 API 合约测试、对应 UI 流程验收与用户文档；不以“后端函数能调用”算闭环完成。
- 当前主题继续沿用 SAO 金色菜单与毛玻璃面板，不在功能批次重新设计视觉体系。
- 本机插件安装是文件级链接，已有产物和新增文件的同步行为不同；部署前核对新增模块、启动检查与回退路径，不能仅凭构建成功报告已加载。
- 本方案不安排立即执行磁盘删除，不迁移现有任务、不合入任何实验。
- 需在各批次设计时落定：核心 bundle 可卸载策略、配置文本秘密处理、跨来源并发资源图、快照父链语义、GC 引用根全集。它们不阻塞 P0/P1 的只读组成和报告展示。

首批建议交付 P0 + P1：用户能看到当前插件、在所选环境升级/卸载、在浏览器内排障，再决定是否合回来源；其余批次单独评审和实现。
