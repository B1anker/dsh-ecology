# World Line 交互约定

界面按用户当前要解决的问题组织。新增功能先确定入口、作用范围、主要动作与结果去向，避免把底层模块名直接变成导航。

## 入口与适用场景

| 用户的问题 | 入口 | 默认范围 |
| --- | --- | --- |
| 不知道环境哪里出了问题 | 维护 → 检查环境 | main，只读检查 |
| 要回到之前可用的状态 | 维护 → 恢复稳定版本 | main，选择恢复点后确认 |
| 安装、合入意外中断 | 维护 → 修复未完成的操作 | main，选择中断记录后确认 |
| 要找出导致故障的变更或插件 | 维护 → 定位故障变更 | main，在隔离实验中排查 |
| 要迁移配置、验证更新或准备外部部署 | 维护 → 迁移、升级与独立部署 | 迁移与升级默认 main；部署作用于当前 profile 的外部启动器 |
| 要释放空间、找回隔离对象 | 环境菜单 → 存储 | 明示当前环境；清理快照与回收对象分别解释用途 |
| 要看操作进度或结果 | 任务台 | 全部环境，每条任务标明操作对象 |

从具体任务进入相关记录时保留该任务的来源环境。验证实验进入环境工具时使用它的来源环境。部署始终说明全局范围，不能显示成仅影响某条分支。

## 页面层级

- 一个页面对应一个用户目标。标题与内容一致，不在页面内并列无关目标的 tabs。
- 维护首页先给出常用问题与适用场景；迁移、升级、部署收进二级入口。
- 插件升级是升级页的主要流程，指定 DSH 版本的兼容验证放入高级选项。
- 任务卡片以“查看进度与结果”为主要动作；报告、差异和相关记录放入展开项。
- 原始 JSON、记录编号、永久清理命令与已处理记录默认折叠，保留明确入口。
- 不在存储、插件、实验、任务等无关页面重复放置整组恢复、排障入口。

## 状态与返回

- 主动打开维护时展示干净的目标首页；从任务进入时展示该任务。
- 进入子功能保留返回路径；返回后仍知道自己来自哪里。
- 异步结果必须属于当前功能和环境。离开页面或切换范围后，旧请求不能覆盖当前数据或错误。
- 确认仅对应眼前的操作对象。切换功能或恢复记录后重新确认，不能继承上一次勾选。
- 空列表说明为什么没有内容；读取失败提供重试；不能把“未读取”当作“没有记录”。
- 完成任务提供可以直接打开的结果入口。导入任务去验证报告，不能重新带回导入表单。

## 弹层与视觉

- 弹窗材质只在 `src/client/panel-material.ts` 定义；布局样式不能重复设置弹窗背景、模糊或阴影。透明度只作用于底色，不作用于整个弹窗；修改后运行 `panel-material.test.ts` 并检查实际计算样式与画布透出效果。

- 垂直字段统一使用 `--wl-field-label-gap`（6px）分隔标签与控件，输入框、下拉框、文本域和文件选择保持一致；复选框和单选框保持同行布局。

- 关闭按钮复用 `CloseButton`，仅移除按钮最外圈边框，保留内部菱形装饰、毛玻璃背景与旋转动效；悬浮反馈和键盘焦点清晰，沿用现有 SAO 风格。
- 点击空白或 Escape 按层级关闭最上层可关闭的弹层；关闭受限的操作仍保留原保护条件。
- 菜单动效复用现有封装，保持逐项切入、切出和边缘淡化，不单独重写时序。

验证新入口时检查：直接进入、返回、关闭重开、空状态、错误重试、作用环境和结果去向。涉及写入的保护条件仍由既有业务流程负责。
