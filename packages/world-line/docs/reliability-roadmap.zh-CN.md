## 1a：文件交换中断恢复

原实现的失败处理会忽略备份还原错误、继续删除备份，并宣称“已回滚”。现已改为：

- 在 profile 内建立 0700 暂存目录，原文件与候选文件以 0600 保存；先持久化原文件和内容哈希记录，再开始逐文件替换。
- 文件和目录同步失败会报告错误。普通进程退出留下 prepared 记录；完成交换后持久化 committed 状态，再清理备份。
- 显式恢复先检查整个文件集合及备份哈希。当前内容只能是已记录的原始内容或候选内容；外部编辑、符号链接、损坏备份均停止恢复并保留现场。
- 恢复中再次退出可重试。已提交记录只完成清理，不覆盖后来的用户编辑。
- 已知未完成交换会阻止后续操作和快照创建，避免把混合状态录成基线。doctor 以失败项列出记录。
- 未带有效记录的旧暂存目录或准备阶段残留只报告人工检查，不凭目录名推断恢复方式。

CLI 使用与其他命令相同的 `--dsh-home` 和 `--profile` 选项，明确选中需要恢复的环境：

```sh
world-line --profile web recovery list
world-line --profile web recovery rollback .wl-staging-012345abcdef --yes
```

示例 ID 需替换为 list 返回值。恢复同时取得操作锁和 profile 写锁；活动写锁不可覆盖，旧进程留下的失效锁沿用显式 `--break-stale-lock` 机制。恢复结果中的 `runtimeVerified: false` 表示仅恢复受管文件，未执行依赖安装、重启或浏览器验证。

测试覆盖逐文件中断状态、两处真实子进程 SIGKILL、外部修改、损坏备份、备份软链接、恢复再次中断、提交后清理、文件权限和 CLI 确认/写入拦截。全量 302 项测试通过，随后新增的提交 fsync 故障注入测试通过（当前交换专项 15 项）。类型检查、构建、lint 错误检查和 diff 空白检查通过。所有破坏性测试均使用临时目录；未对实际用户实验执行恢复或重启宿主。

## 1b：promote 事务恢复

事务记录存放在**实际来源 home** 的 `world-line/transactions/<id>/`，关联 manager home、来源分支、profile、lab 和前后快照。Web 任务在首次修改前持久化 transactionId；安装后自动合入、手动合入和还原后合入共用此关联。原始受管文件保存在该事务的私有备份目录中；即使快照因无加密密钥而跳过秘密文件，事务回滚仍可恢复原字节。结算完成后删除原始备份，保留不含文件内容的事务记录。

记录依次覆盖准备、交换、安装、启动验证、验证完成、合入后快照、决定提交和结算。合入后快照改在安装及可选重启验证结束后生成，避免记录安装器改写之前的内容。`committing` 是持久化的提交决定：此后失败只允许补记状态和 journal，不再悄悄回滚已决定提交的内容。journal 使用独立锁、fsync 和按事务 ID 幂等追加；破损尾行或冲突 ID 停止补记。

未决定提交的事务可以显式恢复原始受管文件；原文件和候选文件之外的内容均视为冲突，保留备份供检查。恢复自身再中断也能重试。已完成事务的重复恢复只清理残留备份，不会把后来的最新快照或稳定点倒退。事务引用纳入源 home 的保留/GC 根；未知格式、损坏记录和命名空间不符均拒绝继续。

```sh
world-line --dsh-home <来源-home> --profile web recovery list
world-line --dsh-home <来源-home> --profile web recovery reconcile <事务-id> --yes
```

失效锁仍需显式 `--break-stale-lock`，活动写锁不可覆盖。若停在 installing/verifying，安装器或验证进程可能仍在运行；先停止相关进程，再用 `--runtime-stopped` 明确确认后重试。此确认不能绕过文件哈希冲突检查。恢复不会自动安装依赖、启动实例、重放任务或宣称当前实例健康；返回 `runtimeVerified: false`。

任务台读取持久化记录：已提交的事务恢复为成功，已回滚的事务显示“受管文件已回滚；实例需要重新验证”，其余显示中断阶段及 CLI 恢复入口。doctor 会列出未完成事务，新的来源操作和普通快照会被拦截。Web 中断恢复已接通，显示范围、确认停止及失效锁选项，并提供重验入口；旧任务没有事务关联时仍保持 interrupted，不能猜测其结果。

验收覆盖八个真实子进程 SIGKILL 边界（交换前后、安装前、启动验证前、验证后、快照后、提交决定后及结算后），快照/稳定点/journal/任务对账、恢复幂等性、秘密原字节回滚、提交后元数据异常、安装器最终内容、外部写入冲突及损坏记录阻止引用收集。均使用临时 home 和假宿主/探针，没有合入或恢复用户真实环境。断电级文件系统故障和残留真实安装进程处置尚未做实机验收。

本批最终全量 314 项测试通过，类型检查、构建、lint 错误检查和 diff 空白检查通过。已同步本机安装目录中 15 个缺失或不同的构建产物（含 8 个新增恢复/事务产物），安装路径直接导入事务模块通过。宿主没有重启，运行中的进程仍需重启后加载新代码。

后续阶段继续遵守：漂移基线与健康基线分开；trace 可能包含秘密，不自动作为已脱敏报告分享；共享 store 不共享可写安装文件；二分允许 good/bad/skip 并复验端点；导入必须先进入实验，秘密通过声明所需输入重新提供。


## 2：按需漂移检测与浏览器失败工件

组成面板和 doctor 分别比较“最近记录”和“已验证稳定点”，两者不可互相替代。比较受管配置、home 配置及快照记录的本地插件源码指纹；旧的 contentHash 仅覆盖插件 package/config，不能用于宣称源码未变化。旧基线缺少源码记录、基线损坏/跨 profile、活动锁、未恢复事务或读取期间发生变化时，不报告一致。比较只读，不创建快照、修改稳定点或监听所有环境；用户打开组成面板或执行诊断时读取。运行内存、数据库、node_modules 全树、远程依赖服务不属于该比较的覆盖范围。

浏览器探针在导航前启动 Playwright tracing，记录截图和 DOM 快照但不附带源码；成功时丢弃记录，失败、导航异常、登录阻塞等证据不足情况保留 viewport 截图和 trace。实验验证及正式来源的重启验证均接入；索引标明环境来源。辅助采集失败不改变验证判定。

工件位于 lab 的 `logs/browser-artifacts/probe-<时间>-<随机值>/`，目录 0700、文件 0600。其中 `index.json` 为索引，`trace.zip` 和 `failure.png` 是原始私有内容，可能包含页面文字、登录信息及网络数据。报告只列最近 30 组工件的环境、时间、路径、大小，不内嵌二进制内容；拒绝跟随工件软链接。复制或下载脱敏 JSON 不携带原始 trace/截图。

工件当前使用本机文件路径访问，可用本机 Playwright Trace Viewer 打开 trace；没有 Web 原始工件下载/预览入口，也没有自动清理历史失败工件。成功探针只删除自己刚创建的临时目录。

验收：全量 323 项测试通过，随后工件环境标记专项通过；类型检查、构建、lint 错误检查及 diff 空白检查通过。覆盖基线独立性、只读性、本地 index.js 变化、并发/损坏状态、工件生命周期、权限及报告不包含原始内容。真实 Chromium 在临时 HTTP 页面生成失败 PNG 与 trace ZIP，ZIP 完整性检查通过。未访问真实用户页面或执行真实插件变更；本轮未重启宿主。


## 3：共享下载缓存与独立安装树

新实验 manifest 记录 `packageStore: shared-copy-v1`。验证的 add/update/remove、镜像首次 install 以及实验子进程环境统一使用 manager home 下的 `world-line/cache/pnpm-store`。缓存在 labs 目录之外，销毁单个实验不会删除它。没有该字段的旧实验保留原 store，未知策略拒绝执行，不静默迁移既有 node_modules。

安装参数固定 clone-or-copy（支持克隆时使用 CoW，否则复制，不退回硬链接）、每个 profile 内的独立 virtual store、关闭全局 virtual store、关闭安装脚本副作用缓存、开启 store 完整性校验。对应环境变量覆盖继承值，兼容 pnpm 10 的 npm_config 与 pnpm 11 的 pnpm_config 前缀，供宿主后续触发安装使用。此处采用 [pnpm 的包导入配置](https://pnpm.io/settings#packageimportmethod)，不复制或共享正式环境的 node_modules。

共享缓存用于同一用户的实验，不是恶意插件沙箱。显式允许脚本仍具有该用户权限；完整性校验不能阻止同一用户进程蓄意修改整个缓存。默认忽略脚本的规则保持不变。Web merge 的一次性候选目录仍用独立 store；没有自动缓存 GC、全目录 CoW 克隆或既有实验迁移。

验收：326 项测试通过。真实 pnpm 11.25.0 使用临时本地包服务：只下载一次，关闭服务后两个新目录离线安装成功；三个安装目录不共享可写文件，修改第一个目录后兄弟目录与后续缓存安装保持原内容。第三次安装只使用子进程环境配置，验证宿主自动安装路径；修正 pnpm 11 配置前缀后专项测试与实测通过。类型检查、构建、lint 错误检查与 diff 空白检查通过。没有安装真实插件、合入正式环境或重启宿主。
