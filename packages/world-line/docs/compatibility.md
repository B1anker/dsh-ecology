# Host-adapter compatibility

`@seaveyon/dsh-world-line` never guesses how DSH works: every layout fact it
relies on is either exported from an exercised DSH package or asserted
byte-for-byte against real behavior in `scripts/evidence.mjs` (transcript and
assertion log: `evidence/live-evidence.json`, regenerated by `bun test:real`
when a `dsh` binary is on `PATH`; CI without DSH skips it cleanly).

## Exercised hosts: DSH 0.1.2-rc.1 and 0.1.5-rc.1

Adapter id `dsh-0.1.x`, `testedVersions: ['0.1.2-rc.1', '0.1.5-rc.1']`. The
facts below were collected from the real 0.1.2-rc.1 installation, re-read from
the 0.1.5-rc.1 packages (`@deepseek-ai/dsh-app-boot`'s `PROFILE_TEMPLATES`,
`DEFAULT_PROFILE_BUNDLES`, filenames, and the root-config bytes the launcher
rewrites are byte-identical between the two), and re-asserted live against each
(`evidence/live-evidence.json` records which binary produced it). The evidence
script derives the version it asserts from `dsh --version`, so a binary outside
the evidence set fails the first assertion instead of silently passing.

What 0.1.5 changed in a freshly initialized profile is content world-line
snapshots but never asserts: the initial `cordis.patch.yml` gained a comment
header above its `[]`, and the initial `pnpm-workspace.yaml` gained
`nodeLinker: hoisted` / `autoInstallPeers: false`.

| fact | value | evidence |
| --- | --- | --- |
| version output | `dsh --version` prints exactly one version from the evidence set | `dsh-version` transcript |
| home resolution | explicit `--dsh-home` > `$DSH_HOME` > `~/.dsh` (`@deepseek-ai/dsh-home-paths`) | package contract (read from the real install) |
| profile directory | `<home>/profiles/<name>`; names reject `""` `.` `..` `node_modules` and path separators | `src/fs/paths.ts` + unit tests |
| profile manifest | `package.json` with `dsh.profile.bundles` (ordered) and optional `dsh.profile.patchReload` | written byte-checked by evidence against `PROFILE_TEMPLATES.web` |
| user patch layer | top-level YAML entry list in `cordis.patch.yml`; loader-patch dialect with `!!js` scalars, ids, disabled flags, insert lists | parse/redact unit tests; real boot reads our edited patch |
| derived root config | `cordis.yml` is *rewritten on every boot* to a fixed template (`# dsh profile root — an empty entry list…[]`) | evidence asserts the file dsh wrote equals our `rootConfigTemplate` byte-for-byte, before and after a user edit + second boot |
| shipped templates | `acp`, `web`, `headless`, `sdk`, `sdk-minimal` with bundles/reload as in `PROFILE_TEMPLATES` | equality of `adapter.profile.templates` against the real export |
| default bundles | `@deepseek-ai/dsh-base` | `DEFAULT_PROFILE_BUNDLES` |
| boot side effect | `dsh --profile X --dump-config` initializes a missing profile from the template without network or node_modules (global fallback resolution) | evidence transcript |
| patch parsing | JSON schema extended with the `!!js` scalar tag; expressions parse to `{__jsExpr}` and are **never evaluated** by world-line | composition unit tests |

Read-only world-line commands (`doctor`, `snapshot create`, `timeline`)
remain available for unknown DSH versions — they degrade to warnings. Later
phases that must *guess* parameters (labs, promotion) fail closed until a
matching adapter evidence set exists (invariant 7).

## What world-line never assumes

- No hardcoded home, ports, tokens, or DSH-internal paths.
- No assumption that `dsh` is installed: detection walks `$PATH`, reads
  `dsh --version` with a 15 s timeout, and treats "no binary / no parseable
  version" as an undetectable-version condition.
- No assumption that a profile has `node_modules` or a lockfile; both are
  optional at capture time and recorded as such.

## Future hosts

Adding adapter support = a new `src/host-adapters/<id>.ts` with its own
evidence transcript (real boot, real boot-rewrite bytes, template export
equality) before the adapter is marked `known` for that version.
